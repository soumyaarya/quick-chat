## 🚀 Overview
QuickChat makes it effortless to create secure chat links and start conversations in seconds. It was designed from the ground up to handle high concurrency by decoupling the real-time WebSocket layer from the heavy database operations using Apache Kafka and Redis.

## ✨ Features
- **Instant Chat Rooms:** Create a secure, passcode-protected chat room in one click.
- **Real-Time Messaging:** Lightning-fast message delivery using WebSockets (`Socket.io`).
- **OAuth Authentication:** Seamless login via Google (NextAuth).
- **Scalable Architecture:** A fully dockerized Microservices backend orchestrated by an Nginx API Gateway.
- **Asynchronous Processing:** Heavy database writes are offloaded to a background Worker via Apache Kafka, ensuring the WebSocket server never blocks.

## 🏗️ Architecture Design

To handle massive scale, the backend is split into dedicated, specialized microservices:

1. **Nginx API Gateway (Port 8000):** Acts as the entry point. It dynamically routes `/api/*` requests to the API Service and `/socket.io/*` requests to the WebSocket Service.
2. **API Service:** A standard REST API responsible for Authentication, fetching Chat History, and creating Groups.
3. **WebSocket Service:** A pure real-time server. It **does not** communicate with the database. It instantly broadcasts messages to users in a chat room, and then pushes the message data into a Kafka Topic. 
4. **Worker Service:** A background consumer that listens to the Kafka Topic. It takes the messages generated by the WebSocket server and safely writes them into the PostgreSQL database at its own pace.

## 💻 Getting Started (Local Development)

### Prerequisites
- Node.js (v18+)
- Docker Desktop (Running)
- Active accounts for NeonDB (Postgres), Upstash (Redis), and Aiven (Kafka)

### 1. Clone the Repository
```bash
git clone https://github.com/your-username/quick-chat.git
cd quick-chat
```

### 2. Environment Variables
You will need to create `.env` files in multiple directories based on the `.env.example` templates (if provided) or populate them with your own credentials:

**Frontend (`front/.env`):**
```env
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your_secret
NEXT_PUBLIC_BACKEND_URL=http://localhost:8000
NEXT_PUBLIC_APP_URL=http://localhost:3000
GOOGLE_CLIENT_ID=your_google_id
GOOGLE_CLIENT_SECRET=your_google_secret
```

**Backend Services (`microservices/services/api/.env`, `microservices/services/websocket/.env`, `microservices/services/worker/.env`):**
```env
PORT=7000 # (7001 for WebSockets)
DATABASE_URL=postgresql://user:pass@host/db
KAFKA_BROKER=your_kafka_broker:port
KAFKA_USERNAME=your_kafka_user
KAFKA_PASSWORD=your_kafka_pass
KAFKA_TOPIC=chats
REDIS_URL=rediss://default:pass@host:port
```

### 3. Start the Backend Cluster (Docker)
Open a terminal in the `microservices` directory and run Docker Compose to build and start the Nginx gateway and all Node services:
```bash
cd microservices
docker-compose up --build
```
*(The backend will now be safely running behind `http://localhost:8000`)*

### 4. Start the Frontend
Open a **new** terminal in the `front` directory, install dependencies, and start the Next.js development server:
```bash
cd front
npm install
npm run dev
```

### 5. Open the App
Visit `http://localhost:3000` in your browser. You can now log in with Google, create a chat room, and start sending lightning-fast messages!
